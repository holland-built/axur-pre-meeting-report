What to run before the call

Five searches and one download. They give you the numbers the customer sees. Twenty minutes, the day before.

What you end up with

One HTML file, and a PDF of the same page. Three cards on the cover, two of them carrying a second number underneath. Each card links to its rows. The customer below is invented.

01

Type the customer

Every query below fills itself in. Copy stays shut until the field that query needs has a value.

02

Run the script

One line writes the whole report. Everything below this is the same job by hand, for when the API key is not ready.

  1. Axur, gear icon, My preferences, API keys, Generate New Key. Copy it once; Axur never shows it again.
  2. Download the script. It arrives with this customer already filled in.

    If the download is blocked, copy instead and paste it into a new file: axur-report.sh on a Mac, axur-report.ps1 on Windows.

  3. Paste one line. It asks for anything it needs and hides the key as you type.
    bash ~/Downloads/axur-report.sh
    powershell -ExecutionPolicy Bypass -File $env:USERPROFILE\Downloads\axur-report.ps1

Tick what you want. The line below fills itself in, and Windows takes the same options as -Brand, -Domain, -DropOwn and so on.

bash ~/Downloads/axur-report.sh --brand BRAND --domain customer.com --save-config customer.conf

The key is not in that line on purpose. A key typed as an argument is kept in your shell history and is readable from the process list, so the script asks for it instead and hides it as you type.

Every run after that, for the same customer:

bash ~/Downloads/axur-report.sh --config customer.conf

It writes a summary page, then the records behind each number, and a PDF if Chrome or Edge is installed. Unless you tick Mask the passwords, the leaked passwords are in it in full. Mac and Windows write the same report.

03

Handle the file like a password

Nothing here is masked, unless you asked for it.

Axur's screen shows only the last character of a password. The export, the source file and the report this script writes all show the whole thing. --mask-passwords is the one exception. It prints the first and last character at most, and nothing at all from a password holding a quote or a backslash. Every account in the file should be reset either way. Send the file the way you would send the credentials, and delete it once the resets are done.

04

By hand: run the five searches

All five run at one.axur.com/threat-hunting ↗. Set the source first. It opens on Files, and the wrong one says Field not found.

Open Threat Hunting in Axur ↗
Exposed credentials
Credentials
Passwords in readable form
Credentials
Impersonation sites
URLs & Domains
Lookalike domains
URLs & Domains
Mail-enabled lookalikes
URLs & Domains

Two of these mislead. Impersonation sites matches any brand whose name contains the word, so read the Impersonated brand column and confirm the rows are your customer. Lookalike domains uses the cleaned field; the plain field returns thousands and is only useful with the mail-record filter attached.

05

Download the attack surface

  1. Open one.axur.com/easm ↗ and switch to Exposures.
  2. Open Hostnames and tick the customer's. There is no select-all.
  3. Click Download all. The file arrives at once, holding exactly what the filter shows.

Do not screenshot the Risk Matrix for a customer. It ignores every filter and always counts the whole tenant.

06

Export the rows you need

  1. Click Export, above the results table.
  2. Type 1,000 in Quantity to be exported.
  3. A link arrives by email, good for seven days. Nothing downloads on the spot.

One credit per hundred rows, counted on the rows that exist. The dialog shows the cost before you commit.
